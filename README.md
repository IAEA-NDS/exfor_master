# EXFOR Master Files

This repository provides a version-controlled snapshot of the EXFOR library as
individual EXFOR entry files. The data are compiled and exchanged by the
[International Network of Nuclear Reaction Data Centres (NRDC)](https://nds.iaea.org/nrdc/)
under the auspices of the IAEA Nuclear Data Section.

The repository was reconstructed from IAEA EXFOR backup files through October
2023. Since finalized TRANS files became publicly available again in 2024, the
`main` branch has been updated from those NRDC transmissions.

These master files are the source data for:

- [EXFOR JSON](https://github.com/IAEA-NDS/exfor_json), generated by
  [EXFOR Parser](https://github.com/IAEA-NDS/exforparser);
- the observable-based
  [exfortables_py](https://github.com/IAEA-NDS/exfortables_py) datasets; and
- the [IAEA Nuclear Reaction Data Explorer](https://nds.iaea.org/dataexplorer/)
  and its [REST API](https://nds.iaea.org/dataexplorer/api/).

## Data provenance and updates

The current data flow is:

```text
NRDC data centres
        |
        v
finalized TRANS files
        |
        v
exfor_master/exforall/<prefix>/<entry>.x4
        |
        v
exforparser
        |-- entry-oriented JSON ----------> exfor_json
        |-- observable tabulation --------> exfortables_py
        `-- searchable data -------------> Data Explorer and REST API
```

The automated update workflow runs daily at 13:00 UTC. When it finds finalized
TRANS files whose release dates have not yet been processed, it:

1. groups the transmissions by release date;
2. downloads each group from the IAEA NRDC TRANS service;
3. creates or updates the affected EXFOR entries and subentries;
4. commits the changes on a date-named branch and merges them into `main`;
5. creates a `Backup-YYYY-MM-DD` tag and a corresponding GitHub release; and
6. regenerates `entry_updatedate.dat`.

No data commit is produced when no new finalized transmission is available.
EXFOR dictionary transmissions (`trans.9...`) are not processed by this
entry-update path.

The implementation in `exfor_trans.py`, together with
`.github/workflows/auto_update.yml`, is the single source of truth for this
repository's update behavior.

## Download

Clone the complete repository:

```sh
git clone https://github.com/IAEA-NDS/exfor_master.git
```

To retrieve only the current snapshot without the complete history:

```sh
git clone --depth 1 https://github.com/IAEA-NDS/exfor_master.git
```

To download only part of the entry tree, use sparse checkout. For example,
entries whose first three characters are `128` can be retrieved with:

```sh
git clone --depth 1 --filter=blob:none --sparse \
  https://github.com/IAEA-NDS/exfor_master.git
cd exfor_master
git sparse-checkout set exforall/128
```

Update an existing checkout to the latest snapshot with:

```sh
git pull origin main
```

Historical snapshots are available from the
[GitHub releases](https://github.com/IAEA-NDS/exfor_master/releases). Release
tags use `Backup-YYYY-MM-DD`; release names use a version such as
`vYYYYMMDD.0`. If more than one release must be distinguished on the same
date, an additional numeric suffix may be used.

## Repository structure

```text
exfor_master/
|-- exforall/
|   |-- 100/
|   |   |-- 10001.x4
|   |   `-- ...
|   |-- 128/
|   |   `-- 12898.x4
|   |-- A01/
|   |   `-- A0144.x4
|   `-- ...
|-- entry_updatedate.dat
|-- exfor_trans.py
|-- config.py
|-- script/
`-- .github/workflows/
```

An EXFOR entry number has five alphanumeric characters. The first three
characters select its directory:

```text
exforall/<first three entry characters>/<entry>.x4
```

Examples:

```text
exforall/128/12898.x4
exforall/A01/A0144.x4
```

### Entry update index

`entry_updatedate.dat` provides one space-separated record per entry:

```text
<entry> <last-update> <revision-count> <git-blob-id>
```

For example:

```text
12898 2023-05-23 4 <git-blob-id>
```

The file is generated from Git history. EXFOR Parser uses its
`last-update` and `revision-count` columns for the JSON fields
`last_updated` and `number_of_revisions`.

## EXFOR entry format

Each `.x4` file contains one complete EXFOR entry, beginning with `ENTRY` and
ending with `ENDENTRY`. An entry contains one or more subentries:

- subentry `001` normally contains entry-level bibliographic information;
- later subentries describe reactions, experimental conditions, COMMON data,
  and tabulated DATA; and
- `NOSUBENT`, `NOCOMMON`, or `NODATA` records mark unavailable sections.

EXFOR is a fixed-field exchange format. Keywords, codes, pointers, units, and
column positions carry meaning; changing whitespace or wrapping lines can
change the record. Use an EXFOR-aware parser for programmatic processing.

The authoritative format description is the
[EXFOR Formats Manual (IAEA-NDS-0207)](https://nds.iaea.org/nrdc/nrdc_doc/iaea-nds-0207-202206.pdf).
EXFOR keywords and codes are maintained separately in the
[EXFOR Dictionary](https://github.com/IAEA-NDS/exfor_dictionary).

## Inspecting entries and history

Read an entry directly:

```sh
less exforall/128/12898.x4
```

Find its update-index record:

```sh
awk '$1 == "12898"' entry_updatedate.dat
```

Show every repository revision of an entry:

```sh
git log --follow -- exforall/128/12898.x4
```

Show the actual changes:

```sh
git log --follow -p -- exforall/128/12898.x4
```

List release tags or historical remote branches:

```sh
git tag --list 'Backup-*' --sort=-creatordate
git branch --remotes
```

## Using the master files with EXFOR Parser

Configure `MASTER_GIT_REPO_PATH` in
[EXFOR Parser](https://github.com/IAEA-NDS/exforparser) to point to this
checkout. The parser resolves an entry through the same canonical path:

```text
exforall/<prefix>/<entry>.x4
```

Convert one entry to the JSON model:

```sh
exforparser --convert 12898
```

Or obtain the parsed entry as a Python dictionary:

```python
from exforparser.json_converter import convert_exfor_to_json

entry = convert_exfor_to_json("12898")
```

Use `exforparser --convert all` to convert the complete snapshot, or
`exforparser --convert updated` to process entries changed since the parser's
stored entry index. Generated JSON belongs in
[exfor_json](https://github.com/IAEA-NDS/exfor_json), and observable-based text
tables belong in
[exfortables_py](https://github.com/IAEA-NDS/exfortables_py).

## Maintainer update tooling

`exfor_trans.py` is repository-maintenance automation, not a read-only user
command. Its normal execution can create branches, commit entry changes, push
to the configured remote, tag releases, and call the GitHub Releases API. The
scheduled and manual GitHub Actions workflows provide the intended execution
environment.

Do not run the updater against a production remote merely to download or
inspect EXFOR data. Ordinary users need only clone or pull the repository.
